개선 계획 · Improvement Plan

디자인 개선, 진행 가능한가?
— 검토와 실행 계획

앞선 리뷰의 지적 사항을 코드베이스 구조에 대조해 실행 가능성을 검증하고, 4단계 실행 계획으로 정리했습니다. 결론부터: 전부 진행 가능하며, 대부분은 생각보다 쌉니다.

1 · 진행 가능성 검토

가능— 리뷰 지적 13건 모두 코드상 개입 지점이 확인됨
  • UI가 격리돼 있다. MVVM+Clean 구조라 모든 지적이 presentation 계층(Compose·theme)에 갇혀 있다. 도메인·스코어링·~2,490개 테스트 대부분은 건드릴 필요가 없다.
  • 테마가 3파일에 집중돼 있다. Color.kt · Theme.kt · Type.kt — 색·서체 계층 변경의 파급 범위가 좁다.
  • 한글 서체 추가가 사실상 공짜다. 앱이 이미 GoogleFont.Provider(다운로더블 폰트)를 쓰고 있어, Google Fonts의 한글 패밀리는 선언 몇 줄로 붙는다.
  • 컴포넌트는 이미 있다. FinanceCard·CarvedTextField·PillTabRow가 DesignComponents.kt에 정의돼 있다 — "새로 만들기"가 아니라 치환 작업이다.
단, 제약 3가지
  • BearSignal 스코어링·임계치는 불가침. bear_thresholds.json과 스코어링 함수는 골든 테스트로 가드된 SSOT — 이번 개선은 전부 표시 계층이므로 충돌 없음. 단, 화면 재구성 시 ViewModel 파생 상태만 추가하고 계산 로직은 무접촉으로.
  • 차트 색은 흩어져 있다. MPAndroidChart 색이 여러 AndroidView 콜백에 하드코딩 — 공통 ChartTheme 헬퍼를 만들어 한 곳으로 모으는 선행 작업 필요.
  • 화면 재구성(3단계)은 중간 리스크. 홈 히어로·BearSignal 2단계화는 상태 배선 변경을 수반 — UI 스모크 테스트와 에뮬레이터 QA를 같은 PR에 묶어야 한다.

3 · 4단계 실행 계획

P1

파운데이션 — 토큰·서체·차트색·대비

난이도 하 · 1~2일 · 리스크 최소

한글 디스플레이 서체 페어링(아래 후보 3종), "경고" 오렌지의 테마 토큰화(ExtendedColors 편입), MPAndroidChart 색 헬퍼 신설 후 청자 팔레트 리매핑, 저대비 캡션 색 상향(#A8A4A0→#BDB8B2 수준). 전부 값 교체 — 레이아웃 무변경이라 회귀 위험이 가장 낮으면서 체감은 가장 크다.

P2

컴포넌트 통일 — 카드 동물원 정리

난이도 중 · 2~3일

기본 Card+surfaceVariant.copy(.5) 사용처를 FinanceCard로 일괄 치환(홈부터), FilterChip↔PillTabRow 역할 규칙 확정(내비=Pill, 필터=Chip 한 스타일), 검색창을 CarvedTextField로 교체, SectionHeader에 title+subtitle 2단 API 추가 후 BearSignal 서술형 헤더 이관. 기계적 치환 위주 — 화면별 diff가 커서 PR을 화면 단위로 쪼개는 걸 권장.

P3

화면 재구성 — 위계와 밀도

난이도 중상 · 3~5일 · 디자인 선행 필요

홈 히어로 도입(오늘의 시장+Fear&Greed 중복 통합), BearSignal 요약↔상세 2단계 재편(헤더+선행신호=요약, 나머지는 펼침/탭), 종목분석 내비 3단→2단, "정세 업데이트" 버튼 단일화, 상시 상태문구 조건부화. 코드 착수 전에 개선 시안을 먼저 확정해야 하는 단계 — 아래 5장의 디자인 산출물이 이 단계의 입력이 된다.

P4

검증 — 대비 감사·QA·회귀

난이도 하 · 1일 · 각 단계 말미 반복

다크/라이트 전 화면 대비 감사(WCAG AA 4.5:1, 잔글씨 우선), 에뮬레이터 실기(360dp·폰트스케일 1.3x·다크 — 기존 QA 관례 재사용), feature.bearsignal 패키지 골든 테스트 재실행으로 표시 계층 무접촉 증명.

4 · 한글 디스플레이 서체 후보

셋 다 Google Fonts — 앱의 기존 다운로더블 폰트 경로로 즉시 적용 가능. 실제 렌더링 견본입니다 (다크 카드 = 앱 환경).

오늘의 시장
72 탐욕
본문은 DM Sans + Noto Sans KR 유지
A · Hahmlet 추천

1950년대 한국 영화 간판 글자에서 온 한글·라틴 겸용 세리프. 먹빛·청자·한지라는 테마 서사와 정확히 같은 결. Syne의 기하학적 개성과 대비를 이루는 페어링. 9웨이트.

오늘의 시장
72 탐욕
본문은 DM Sans + Noto Sans KR 유지
B · Gothic A1 (ExtraBold)

단단한 지오메트릭 산세리프 — Syne의 무게감과 가장 유사한 "안전한" 선택. 터미널다운 밀도, 데이터 헤더에 강함. 다만 개성은 A보다 약하다.

오늘의 시장
72 탐욕
본문까지 통일 교체하는 안
C · IBM Plex Sans KR

제목+본문을 한 패밀리로 통일하는 보수안. 개성은 가장 낮지만 한글·숫자 혼용 가독성과 유지보수가 가장 단순하다.
